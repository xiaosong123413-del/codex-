# 同步检测与前后端联动要求

日期：2026-05-04

## 核心问题

同步检测不能由后端写死少数目录决定。前端选择了同步文件夹以后，后端必须读取同一份同步配置，并把这些目录实时纳入新源料检测、同步编译计划和后续来源元数据。

## 必须满足

- 前端“同步文件夹”配置是后端扫描的事实来源。
- 用户新增或勾选任意同步文件夹后，点击同步时后端必须能检测到该文件夹下的 Markdown 源料。
- 后端不能靠新增一个固定目录名来解决问题，例如只写死 `raw/个人信息`。
- 新源料检测弹窗必须展示来自已配置同步文件夹的内容，并显示可理解的来源标签。
- 同步编译写入 `sources_full` 和 `raw_import_manifest.json` 时，来源元数据必须保留原始来源文件夹、相对路径、标题和来源类型。
- 如果前端新增入口或按钮，必须同步明确后端读取什么配置、调用哪个接口、数据进入哪里、后续被哪个流程消费。
- 若前端和后端任一侧无法确认已接通，执行前必须停下确认，不允许只改一边。

## UI 要求

- 除 wiki 文档页外，其他页面的颜色和视觉风格优先向“任务计划页”统一。
- 任务计划页中删除“领域与项目推进”模块，让“AI 智能排期助手”占满对应区域。
- 后续整体美化方向是更克制、清晰、高级，但不能牺牲信息密度和可操作性。

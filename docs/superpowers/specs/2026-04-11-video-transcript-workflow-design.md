# 视频文字稿自动化工作流设计

## 背景

用户希望建立一条固定工作流：以后只要在对话里发送“提取视频文字稿 + 视频链接”，系统就自动在本机执行完整流程，无需用户手动打开网页、下载视频或转写音频。

这条流程必须严格经过指定页面 `https://www.hellotik.app/zh/douyin#google_vignette`，将用户提供的视频链接填入页面输入框，点击“解析视频”，再点击“下载无水印视频”。下载完成后，在本机完成语音转文字，并将结果以 Markdown 文件写入指定 Obsidian 目录。

## 目标

第一版工作流需要实现以下行为：

1. 接收一条包含视频链接的自然语言指令作为触发输入。
2. 自动打开指定 `hellotik` 页面并完成页面交互。
3. 下载无水印视频到本地临时目录。
4. 从视频中提取音轨并在本机完成转写。
5. 生成结构化 Markdown 文稿。
6. 将文稿写入固定 Obsidian 目录。
7. 在网页失败、下载失败或转写失败时留下足够的日志和截图，方便后续重跑。

## 非目标

第一版不包含以下能力：

- 不为不同来源平台创建子目录。
- 不把文稿同步到云端或第三方转写服务。
- 不做批量链接队列处理。
- 不做字幕时间轴精修或句读人工润色。
- 不改写为绕过页面流程的直接抓取方案。

## 用户输入与触发规则

### 触发语句

默认触发模式为：用户在对话中发送“提取视频文字稿 + 链接”。

系统在检测到该意图后，默认执行完整流程，不再重复询问以下固定设置：

- 必须通过 `hellotik` 页面下载无水印视频
- 必须在本地完成转写
- 文稿必须写入指定 Obsidian 目录

### 输入约束

- 用户消息中至少包含一个可识别的视频 URL。
- 第一版只处理单个链接。
- 若消息中包含多个链接，流程应中止并提示当前版本仅支持一次处理一个链接。

## 固定输出位置

Markdown 文稿统一写入以下目录，不创建任何子目录：

`C:\Users\Administrator\Desktop\xiaosong的知识库\raw（只读区）（按照来源分类）\视频转文字稿`

## 文件命名规则

默认文件名格式：

`YYYY-MM-DD_HH-mm-ss_来源平台_短ID.md`

命名规则说明：

- `YYYY-MM-DD_HH-mm-ss` 使用本机当前时间。
- `来源平台` 通过链接域名推断，如 `douyin`、`bilibili`、`xiaohongshu`；无法识别时使用 `unknown`。
- `短ID` 优先从链接中提取稳定标识；提取失败时使用随机短串。
- 若最终文件名发生冲突，追加短随机后缀。

## 文稿格式

每次转写生成一个 Markdown 文件，推荐结构如下：

```md
# 视频转文字稿

- 原始链接: ...
- 下载时间: ...
- 转写时间: ...
- 来源页面: https://www.hellotik.app/zh/douyin#google_vignette
- 本地视频: ...
- 转写方式: faster-whisper

## 正文

...
```

写入要求：

- 必须包含原始链接，便于回溯。
- 必须记录下载时间与转写时间。
- 必须记录本地视频文件路径。
- 必须包含完整转写正文。
- 若转写质量存在明显风险，应在正文前加入提示说明。

## 总体架构

第一版采用以下分层结构：

1. `触发入口层`
   - 接收用户消息并抽取视频链接。
2. `网页自动化层`
   - 使用 Playwright 打开指定页面、填入链接、点击按钮并处理下载。
3. `媒体处理层`
   - 使用 ffmpeg 从下载后的视频中提取音频。
4. `本地转写层`
   - 使用 faster-whisper 对音频执行本地语音识别。
5. `落盘层`
   - 生成 Markdown 并写入 Obsidian 目录。
6. `日志与错误恢复层`
   - 保存截图、错误信息、临时文件路径和可重试上下文。

## 方案选择

### 推荐方案：Playwright + ffmpeg + faster-whisper

选择理由：

- 最符合用户要求的“必须经过指定网页并点击指定按钮”。
- 对动态页面和下载流程的兼容性更强。
- 本地转写满足隐私和离线要求。
- 后续可以稳定补充等待策略、截图、重试和日志能力。

### 备选方案一：浏览器宏 + 本地转写

不选原因：

- 稳定性差，页面变化后更容易失效。
- 错误处理和可观测性弱。

### 备选方案二：直接请求下载地址 + 本地转写

不选原因：

- 不符合用户要求的固定网页交互路径。
- 对页面实现细节过于依赖，长期维护成本更高。

## 详细流程

### 1. 输入解析

- 从用户消息中提取第一个 URL。
- 校验 URL 基本格式。
- 推断平台标识与短 ID，用于命名输出文件。

### 2. 打开目标页面

- 使用 Playwright 启动浏览器。
- 打开 `https://www.hellotik.app/zh/douyin#google_vignette`。
- 等待输入框、解析按钮和页面主区域加载完成。

### 3. 执行页面交互

- 将用户链接填入页面输入框。
- 点击“解析视频”。
- 等待解析结果区域出现。
- 定位“下载无水印视频”按钮或其等效下载入口。
- 触发下载并等待浏览器下载事件完成。

### 4. 保存视频

- 视频先保存到项目内部临时目录。
- 临时目录需要按任务实例隔离，避免并发冲突和重复覆盖。
- 下载成功后记录实际文件名、路径和下载时间。

### 5. 抽取音频

- 调用 ffmpeg 从视频中抽取单独音轨文件。
- 音频输出格式以 Whisper 兼容性优先，可使用 `wav` 或 `mp3`。
- 若抽音失败，流程终止并保留原视频。

### 6. 本地转写

- 使用 faster-whisper 执行本地识别。
- 第一版优先输出纯文本，不强制输出时间戳。
- 若检测为中文或中英混合内容，优先保持原语言输出。
- 若音频为空、噪声过大或识别结果明显不完整，需要在结果文件中写明风险提示。

### 7. 生成 Markdown

- 根据固定模板组织头部元数据与正文。
- 文稿编码统一为 UTF-8。
- 成功后写入固定 Obsidian 目录。

### 8. 清理策略

- 默认保留下载后的视频文件，便于后续核对和补跑。
- 默认清理中间音频文件。
- 若转写失败，则保留视频与音频，便于问题排查。

## 错误处理与重试

### 网页阶段

- 若输入框、解析按钮或下载按钮未出现，自动重试最多 2 次。
- 每次失败都保存页面截图。
- 若页面结构变化导致选择器失效，应在日志中明确记录失效步骤。

### 下载阶段

- 若点击后未产生下载事件，重试下载动作。
- 若下载内容为空或文件损坏，记录错误并停止后续转写。
- 下载失败时保留截图与浏览器日志。

### 转写阶段

- 若 ffmpeg 不可用，直接报错并停止流程。
- 若 faster-whisper 依赖缺失，直接报错并停止流程。
- 若模型推理异常，则保留已下载视频和中间文件，等待后续补跑。

## 日志与可观测性

每次执行至少记录以下信息：

- 原始输入链接
- 任务开始时间与结束时间
- 页面是否成功加载
- 是否成功点击解析按钮
- 是否成功触发下载
- 本地视频路径
- 抽音结果
- 转写结果摘要
- 最终 Markdown 输出路径
- 错误堆栈或截图路径

## 本机依赖

第一版需要准备以下依赖：

- Node.js 运行时
- Playwright 包及浏览器内核
- Python 运行时
- faster-whisper 及其依赖
- ffmpeg

## 与当前项目的集成方式

建议在当前仓库内新增一套独立的自动化脚本，而不是改动现有 Feishu 相关主流程。

推荐组织方式：

- `src/video-transcript/`
  - 放置下载、转写、落盘相关模块
- `scripts/` 或独立入口文件
  - 放置命令行触发入口
- `tmp/`
  - 放置任务级临时视频、音频、截图和日志

这样可以保证：

- 与现有项目职责解耦
- 便于单独调试网页自动化
- 便于后续把“提取视频文字稿”映射为固定命令入口

## 测试策略

第一版至少覆盖以下验证：

1. 链接解析测试
   - 能从触发语句中提取单个 URL。
2. 文件命名测试
   - 能按固定规则生成 Markdown 文件名。
3. Markdown 生成测试
   - 能正确输出头部元数据和正文结构。
4. 网页自动化冒烟测试
   - 使用真实页面完成一次下载流程。
5. 端到端手工验证
   - 从用户输入到 Markdown 落盘全链路跑通一次。

## 风险与边界

- `hellotik` 页面结构可能变更，导致选择器失效。
- 网站可能出现弹窗、重定向或加载缓慢，需要等待与重试策略。
- 本地机器目前尚未安装 ffmpeg 和 faster-whisper，首次落地需要补齐依赖。
- 部分视频可能无音轨、背景噪声重或语音不清晰，导致转写质量下降。
- 若视频受平台、地区或站点限制，下载流程可能失败。

## 成功标准

满足以下条件即可视为第一版完成：

1. 用户发送“提取视频文字稿 + 单个视频链接”。
2. 系统自动打开指定页面并成功下载无水印视频。
3. 系统在本机完成转写。
4. 指定 Obsidian 目录中生成对应 Markdown 文稿。
5. 失败场景下能留下足够日志与截图，便于复现和修复。

## 后续扩展方向

第一版完成后，可考虑增加以下增强项：

- 输出带时间戳的分段文稿
- 自动提取视频标题作为文件名补充
- 支持一次处理多个链接
- 支持更灵活的保留策略，例如保留音频或自动归档视频
- 支持把执行结果摘要直接回帖给用户
